# scene3d · 三维灯光渲染内核

## 来源

原样搬运自内部的三维演示引擎：

```
（原文件：可执行灯光场景.html）
SHA-256 f6a61343ac0c0012c5892248160cdb32c926b995bf651d2c13846d723b72ac86
974,313 字节 / 4,334 行
```

| 文件 | 是什么 | 改动 |
|---|---|---|
| `app.js` | 原文件第二个 `<script>` 的全部内容（776,786 字节） | **零改动**，逐字节验证 `app.js in 原文件` 为 True |
| `shell.html` | 原文件的 `<head>`+样式+DOM 骨架 | 只把最后那句 `window.__SCENE__ = {...}` 换成一个 loader |

`app.js` 的 SHA-256：`bad409e534219bc0484dc1d822c1df35abb08f0aacfb2de040211ab3636227bc`

## 为什么这么接

原文件的场景数据是**外挂**的：一个 190KB 的 `window.__SCENE__` 对象（墙、地面、房间、灯位、
灯带、门窗，坐标单位米）。渲染内核只认这个全局，跟户型没有绑定关系。

所以接入工作台不是"照抄它的光照参数到我们自己的渲染器"，而是把项目数据翻译成它认的那份
JSON：

```
工作台项目 → /api/lighting3d/{pid}/ueyi-scene.json → shell.html → __SCENE__ → app.js
```

翻译层在 `backend/ueyi_scene.py`。内核、面板、六档情景、昼夜、三个视角、回路开关、
剖切高度、截图 —— 全部是原文件的行为，一行没改。

## shell.html 加了什么

只有 loader（约 60 行），三件事：

1. 读 `?project=<pid>&floor=<n>` → fetch `ueyi-scene.json` → 塞进 `window.__SCENE__` → 加载 `app.js`
2. 读 `?scene=<json 地址>` → 直接喂一份现成场景（用来回归对比原文件）
3. 内核启动后点一下「全开」情景（可用 `&preset=会客` 改）

第 3 条是因为内核默认「会客」，而它按回路名匹配房间（客厅/餐厅满亮、其余 15%）。
房间还没命名的项目整屋会压到 15%，一进去像没开灯。

## 改这个目录的规矩

`app.js` 不许改。要调效果只能改翻译层（`ueyi_scene.py`）给的场景数据，或者改 `shell.html`
的 loader。原文件升级时整段替换 `app.js`，重新记 SHA。

## 口径

三维只负责**看效果**，编辑（拖灯、放点、选家具）只在二维平面图上做 —— 现场 2026-10-19 拍板。
