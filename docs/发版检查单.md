# 光律工作台 · 发版检查单

> 每次发 GitHub Release 前逐项打勾；复制一份到本次发版的 issue / 提交说明 / Release 草稿里。
> 规则全文见 [`版本号规则.md`](版本号规则.md)。

## 0. 三问（必须回答，答案抄进 Release 正文）

1. **能一键更新到吗？** 从上一版（以及任意 1.x）点「立即更新」能不能直接装上新版？
   - 能 → 继续 1.x；不能 / 要重装 → **2.0.0**
2. **更新后功能变少、或要重新授权 / 付费吗？**
   - 是 → **2.0.0**；否 → 继续
3. **有用户可感知的新能力吗？**
   - 有 → **1.Y.0（minor）**；没有，只修问题 → **1.x.Z（patch）**

**本次版本类型**：`patch / minor / major`（圈一个）

## 1. 改前

- [ ] 已留本机快照：`version_snapshot.sh --tag pre-github-release-<新号>`
- [ ] 发版仓库是干净 clone / 工作区；`git status --short` 已看，没有旧版残留
- [ ] `VERSION` 已 bump，且只 +1 一个号段
- [ ] `README.md`「当前版本 vX.Y.Z」已同步
- [ ] `frontend/package.json` 与 `frontend/package-lock.json` 的根版本已同步（`--bump` 自动改）
- [ ] `backend/app_versions.py` 的 `RELEASE_NOTES[<新号>]` 已登记，每条有 `category`（fix / feat / breaking；从 1.3.4 起）
- [ ] GitHub Release 说明按模板写好（版本类型 / 依据 / 重点 / 升级 / 数据安全 / 校验 / 已知问题）
- [ ] 如果改了前端：`npm run build` 完成，`frontend/dist` 是最新
- [ ] `version_guard.py --baseline` 已跑（build-baseline 的 version / buildId / asset / sha256 对齐）

## 2. 版本与构建检查（必须全绿）

- [ ] `python3 scripts/version_guard.py --check --strict`
- [ ] `python3 scripts/version_guard.py --check-bump`（非 git 目录加 `--base <上一个已发布号>`）
- [ ] `python3 scripts/build_release.py`
- [ ] `dist-release/` 有 4 件：`guanglv-workbench-<新号>.tar.gz`、`SHA256SUMS.txt`、`apply_update.py`、`guanglv-update.command`
- [ ] `release.json` 的 version / tag / package / sha256 与新号一致
- [ ] 包内 VERSION = 新号；包内不含 `data/`、`.env`、`.venv/`、`node_modules/`

## 3. 提交与 tag

- [ ] 只提交本次发版相关文件；`git diff --stat` 已复核
- [ ] `git commit -m "v<新号>：<一句话>"`
- [ ] `git tag -a "v<新号>" -m "光律 v<新号> · <一句话>"`
- [ ] `python3 scripts/version_guard.py --check-tag "v<新号>"` 通过（annotated / 指向 HEAD / == VERSION）
- [ ] `git push origin main "v<新号>"`（只推这一个 tag，不 `--tags`）

## 4. GitHub Release

- [ ] 用该 tag 建**正式** Release，**不勾 prerelease**
- [ ] 标题：`光律 v<新号> · <一句话>`
- [ ] 4 个资产**先传齐**，再 Publish
- [ ] 正文含：版本类型 / 依据 / 本版重点 / 怎么升级 / 数据安全与回退 / 校验 / 已知问题（无也写「无」）
- [ ] 2.0.0 额外含：迁移 / 兼容 / 回退 三件套
- [ ] 资产 sha256 与 `SHA256SUMS.txt` 对得上

## 5. 发后验证

- [ ] 用上一版装机，走一次「设置 → 检查更新 → 立即更新」，装到新号
- [ ] 版本号、buildId、项目 / 产品 / 版本 / 上传文件逐项与更新前一致
- [ ] 出问题能回退（「光律-回退版本.command」或 `version_rollback.sh --to <id>`）
- [ ] 留发后快照：`--tag github-v<新号>-released`
- [ ] `光律版本库/history.tsv` 记录 tag / buildId / 校验结果
